# ECN 模块职责

入口与 URL 保持 `src/pages/ecn_management.py`、`/ecn_management`。根目录业务 JSON、权限模块和通用审批接口不搬迁。

## 写入约定

`actions` 的服务返回 `ECNResult`。成功后使用返回的已提交单据更新界面；失败时显示消息并保留输入，不能把 `ATOMIC_NO_UPDATE` 当作业务保存成功。

新建窗口不预占编号，首次保存使用集合级事务完成“分配编号 + 插入”。并发用户可以同时创建，编号按提交时的日期和日序号生成。

影响字段使用 `current / baseline / submitted` 三方合并。不同字段的修改保留；相同字段的不同修改报冲突。扩展项目按实际新增/移除合并。轮询只能同步未编辑字段，并保留正在输入内容的原始基线。

方案更新/删除必须匹配打开窗口时的方案快照；确认时核对本人当前方案；发起评审在事务内检查最新参与者和方案覆盖率。每条方案必须关联至少一个项目，变更要求、资料和物料允许按单条方案留空；覆盖率按全部方案并集要求所有项目、变更要求、强制资料和物料影响均至少被一条方案关联。扩大影响项目保存及发起评审时按最新项目库复核存在性和状态分组。新增影响项只形成覆盖缺口并阻止发起评审；删除已关联影响项时自动移除方案中的失效关联，标记对应方案及作者待复核，作者必须选择确认保留、编辑或删除后才能再次确认；项目已全部移除的方案不能确认保留。系统内资料方案的 `projects` 与 `project_states` 必须一致，所有关联在保存和发起评审时均按最新单据范围校验。表格子参数引用待新增基准行时，保存、删除和发起评审均复核基准方案仍在同一项目新增对应首列；执行固定先完成基准方案，依赖失效或执行失败时拒绝创建子项，不生成孤立兜底行。每次提交有独立 `approval_round`，旧轮次页面不能继续审批。

ECN等级使用稳定编码保存，JSON只修改显示名称。未判定按一般等级运行；简单等级的ECR与方案评审分别使用独立数据库流程事件。ECR审核中切换简单/非简单等级必须在同一业务事务中重建审批待办。复杂等级可指定方案验证报告，作者上传后由同时具备查看和审批权限的其他人员审批；所有指定项通过后才满足方案评审门禁。

等级判定窗口固定保存打开时的单据快照，保存事务比较等级原值及判定历史，已被其它页面修改时明确拒绝；等级改回原值也不能绕过历史比较，无关字段变化不冲突。关键写入口必须同时实时校验在职、ECN查看权限与对应操作权限；页面入口检查不能代替事务内校验。保存/审批/料号/等级/验证报告、执行启动与确认、审批改派和删除均遵循此规则；后端拒绝时不得修改单据或具体审批待办。

影响范围删除使方案项目、要求、资料、物料关联或逐项目配置被自动删减时，同一事务内撤销受影响方案的验证报告审批结论；保留已有附件，有附件转待审批，无附件转待上传，清除旧审核人、时间及意见。不受影响方案和未指定报告不重置；作者确认保留不能恢复旧审批结论。

`db_storage.atomic_deep_update_transaction` 的回调持有 SQLite 写事务，只允许使用提供的连接执行关联表写入。`ApprovalTransaction` 的同步方法只记录待办命令，`flush` 才使用该连接实际写入，避免同步/异步连接相互等待，并确保失败同时回滚单据与待办。数据库模式的物料执行清单从七个已发布 `ecn:execution_*` 流程生成，并在每个责任项中固化流程编码、版本、节点及具体人员；根目录执行路线仅供旧模式和首次迁移。

客户/在途流程中的“项目销售 → 销售主管 → 销售总监”是一条逐级兜底责任链。流程同时配置项目销售和销售主管节点时，只固化项目销售任务；当前销售缺失、停用、离职或无权限后，在该任务上逐级解析下一位可处理人，不额外生成销售主管并行任务。项目销售任务上提后的复选框与企业微信待办统一显示“项目 · 姓名（代确认）”，不在主标签显示原岗位；其它物料责任项沿上级传导时也显示“姓名（代确认）”，具体责任来源和传导原因留在 tooltip。

系统内资料跨项目执行仍采用逐项持久化与幂等重试，并非所有概述变更的单一事务。同一项目参数的替换在一次原子更新中同时失效旧节点和创建新节点；每个项目完成后立即写回 ECN 检查点，重试通过确定性节点 ID 和 ECN 来源标记跳过已完成操作。更换或失效方案保存时在同一 SQLite 事务中复核目标概述快照和其它 ECN 占用；未完成方案从最新 ECN 单据动态形成概述写锁，普通概述写入口通过 `overview_storage` 在自己的事务中读取该锁并拒绝修改，ECN 自动执行通过该业务入口显式声明放行。`db_storage` 只提供通用事务能力，不识别 ECN。方案改选、删除、执行成功或单据结束后锁随单据状态自然释放，不保存可能残留的第二份锁记录。

动态写锁同时派生新增/替换结果的确定性节点ID，覆盖正式概述落盘到ECN检查点持久化之间的窗口，完成检查点后随方案执行状态释放。每次落盘在对应来源历史中保存最终内容及状态指纹（上传类包含发布后的文件元数据），缺失检查点的重试必须核对来源及指纹；替换同时检查旧节点失活结果和新节点，不一致则保留现场并报告失败，不能仅凭来源标记认定成功。

ECN 附件根目录与单文件大小限制由 `ecn_management_config.json.attachments` 配置。文件按“上传人 / ECN 编号 / 业务位置”归档，以 UUID 独立文件名避免重名与共享；原文件名和上传人保存在单据附件元数据中。新建 ECR、普通资料方案弹窗的上传先暂存，单据或方案保存成功后归档；取消时清理暂存，保存失败时清理本次归档副本并保留暂存供重试。删除方案或整张单据在业务事务成功后清理能验证 UUID 独占命名的文件。已保存单据的附件逐条在最新数据库记录上验证账号、阶段和责任人后追加。ECR 申请人编辑草稿或驳回单时直接在表单中查看与上传；审核及后续阶段只直接展示已有附件，无附件时隐藏该区。方案表格的蓝紫色附件图标只供查看；方案编辑弹窗左右展示旧附件清单和上传控件，文件行留有间距。执行阶段的特定事项、ERP 和物料节点在勾选框右侧最多显示一个附件按钮：青绿色上传图标供负责人查看并上传，蓝紫色回形针仅在有附件时供其他人查看；上传或删除成功立即更新按钮悬停数量。系统内资料执行结果不显示附件按钮。图片可点开大图，PDF 在新标签页打开，其它文件点击下载；图片/PDF 的短时预览链接在每次读取时重新核对当前权限和文件状态。

物料方案的料号不是发起方案评审的前置条件。新增方案可逐行维护“新增替换料”，更改方案可分别维护“更改前替换料”和“更改后替换料”；每行使用稳定ID保存料号与物料名称，并在方案及执行对照表的对应内容中展示。评审通过后，主物料或任一替换料缺少料号时，单据停留在独立料号补充阶段；`ecn.material_code.edit` 控制处理人、首页待办和企业微信提醒，授权人可在同一窗口补齐或修改主物料及替换料料号。补充操作按方案打开时的料号及替换料结构快照检查并发冲突，最后一项补齐与执行清单生成在同一单据事务内完成，执行阶段拒绝继续修改。

## 验证

物料执行任务按“追溯范围 + 流程节点编码 + 项目（如适用）”生成唯一标识，不使用责任名称作为键；同名节点仍独立执行。节点配置 `all` 时为每名具体人员生成独立会签确认项，全部完成才推进阶段或关闭方案；`any` 保持任意一人完成的负责人池。会签项继续复用确认、撤销、复核、改派、附件和提醒入口，界面显示人员姓名；项目销售兜底依据明确的责任来源字段判断，不能从内部任务键反推。

未移交的资料/ERP项被执行复核撤销后，执行助理可在概述失败或物料阶段直接重新确认该退回项，不需要先移交，也不重跑已经成功的概述方案。页面、后端确认、首页待办及企业微信共用同一可处理判定；未退回的普通未移交项仍只允许在第一阶段处理。重新确认后沿用原关闭及最终核验流程。

系统内资料上传先进入独立暂存；保存方案前检查正式目录，同名时由用户选择使用已有文件、改名保存上传文件或取消。选择已有文件时归档的是已有文件的内容，保证评审内容与执行内容一致。方案保存文件名、目录、来源及 SHA-256；获批执行时复核，再按确认名称发布或引用正式文件，不再按项目生成 UUID5 名称。目录改变、已有文件被删除或同名内容改变时拒绝执行，不覆盖、不自动恢复。UUID 仅用于隔离送审归档，指纹只校验内容。概述归档和正式文件不随失败、删除方案或整单清理；可清理独立暂存及未发布半成品。普通非概述附件保持上一段的清理规则。ECN 未部署，不提供旧 ECN 文件选择兼容分支。

新增表格子项对已有基准行和本单待新增基准行都形成动态依赖；普通写入口不能修改被依赖的基准行，方案保存/评审/执行会复核基准行仍有效，同单基准行失效方案与子项新增互斥。执行中的单据禁止删除，且每个项目的概述落盘事务内必须从数据库复核单据存在、执行阶段、批次及方案业务快照；旧批次与已删单据不得继续写入。验证报告审批同时核对打开审批窗口时的报告和方案业务快照，方案已变更时必须重新查看。

特定事项及ERP默认由执行助理确认；助理可移交给一名在职且有ECN查看权限的具体人员，移交后仅接收人确认。系统内资料只等待未移交项完成，移交项不阻挡推进；所有特定事项和物料完成才关闭ECN。系统内资料启动后仍可更换未完成项接收人，但不能收回为未移交项。移交/确认使用打开窗口或渲染控件时的快照，在最新单据事务中校验。

负责人变更时，将原负责人取消告知事件与单据同事务保存；新负责人通过正常待办扫描收到提醒，两类通知均沿用调试与经理抄送开关。取消告知按单据/事件/实际收件人记录去重与失败重试；抄送开关变化不重发原收件人通知，抄送失败只重试该收件人。原收件人同时命中经理抄送时仍只发送一张本人通知，不标成抄送。旧接收人已重新接回该事项时跳过过时取消告知。ECN 尚未正式部署，不迁移旧版按路由存储的本地测试通知状态。总表“特定事项”列位于“文件”之前，显示完成数量并打开独立确认窗口。回归见 `tests/test_ecn_special_tasks.py`。

取消卡片使用同一套业务字段摘要，并明确无需继续处理。操作人回收给本人时，只豁免该事项给本人的微信待办（在调试/抄送解析前过滤），保留原负责人取消告知和页面待办；其他待处理事项仍正常提醒。豁免记录随下一次负责人变更更新。

执行待办会动态复核负责人状态和稳定权限。具体接收人被停用、离职或失去ECN查看权限时，特定事项标红并保留执行助理的调整入口；当前物料节点无人具备确认资格时，在执行表标红并允许执行助理按部门、岗位选择具备ECN执行权限的在职人员。人工改派写入节点历史和审批日志，确认时仍在最新单据上复核具体人及权限。首页把异常单据显示为“负责人异常·待改派”，企业微信按同一口径提醒执行助理；岗位池内仍有其他合资格人员时不误报异常。

执行复核不改写原确认历史。拥有 `ecn.execution.verify` 的人员只能撤销当前仍为已确认的执行项，必须填写理由，附件可选；撤销事件、原确认人、复核人和附件统一进入 `execution_info.verification.history`。撤销关闭单据时恢复执行阶段，原责任人重新确认后仍使用既有关闭逻辑。最终“已核验无误”只能在所有执行勾选项完成且单据重新关闭后提交。撤销通知保存为业务事件并由后台幂等发送，原确认人不可送达时沿直属上级链逐级传导。

首页列表、执行详情和企业微信扫描在每轮开始时一次性读取在职用户及有效权限，并在本轮全部责任项判断中复用；不得在“单据 × 节点 × 用户”循环内逐项打开SQLite连接查询权限。具体确认、改派等写操作仍绕过快照，在最新事务中重新校验实时权限。

ECN微信使用文本卡片，标题标识模块与当前待办，灰色说明标识经理抄送；摘要按UTF-8字节限制并转义用户内容，底部查看详情进入ECN列表。`public_base_url` 为空时回退文字提醒。卡片沿用原去重指纹与ECN业务重试，升级不强制重发旧通知。`tests/test_wecom_cards.py` 验证实际请求结构、失败返回以及原文本协议不变，全部模拟网络。

物料执行提醒不展示内部方案UUID或责任项键，统一转换为“方案编号、项目、变更类别、追溯范围、确认节点”。个人通知只汇总该微信账号对应人员的待办；研发经理抄送按实际待办人员逐人镜像，待办最多预览3项并提示进入系统查看其余内容。

企业微信配置位于根目录 `ecn_management_config.json` 的 `wecom`：默认 `enabled=true`，收件人由首页实际待办判断与企业微信绑定决定；不会更改首页角标或审批权限。旧调试路由已删除，本地调试统一由 `/dev/identity-switcher` 在发送出口拦截或转发。正式人员未绑定微信时跳过，不回退给其它人员。

系统账号 `admin` 的自动全权限只用于管理操作，不代表业务责任。ECN普通待办、特定事项取消、执行复核撤销、项目销售及流程完成岗位抄送在解析业务收件人时均排除 `admin`；管理员页面权限不受影响。调试模式配置的是实际研发经理收件规则，不因排除系统账号而关闭。

正式模式默认 `cc_manager_enabled=true`，同时抄送通讯录职务为“研发经理”的人员。观察抄送按原待办人员逐人镜像：实际处理人收到什么内容，研发经理就收到该人员对应的一张抄送卡片，不把多人待办汇总成一张。经理本人有实际待办时，其本人待办不重复抄送；调试模式不额外抄送，抄送解析失败不影响正式提醒。观察结束改为 `false` 并重启即可停止抄送及其失败重试；开关变化不触发正式人员重发，重新开启仍遵守经理账号原有的重复间隔。

系统启动30秒后首次检查，随后每60秒检查；通知状态按“ECN、原待办人员、具体任务、投递路线”分别记录。物料责任项去重使用方案ID与节点任务键，不能只比较显示文案；同名顺序节点切换后必须视为新责任，同名并行节点分别保留标识。个人新增待处理责任时立即进入下一轮提醒；本人完成任务导致任务减少时只清理对应标识，不提醒本人，也不重置其他人员的24小时计时。已经消失的责任以后重新出现时视为新待办。同一项持续待办每24小时最多重复提醒一次。通知状态独立保存在 `ecn_wecom_notification_state`，不修改单据；数据库中的发送占用标记避免重复执行。失败默认300秒后重新检查当前待办再重试；成功后清除失败重试退避，不能阻挡下一项新责任通知。链接打开 ECN 列表，正文提供单号便于查询。上述时间均可由 JSON 调整，重启生效。

系统内资料执行取得运行标记后，启动提示、首次重绘、读取、落盘及结果展示统一包含在清理范围内。无论异常、提前返回还是协程取消，都清除本进程运行标记；数据库批次和租约继续保留，避免取消时尚未结束的写入与恢复重叠，租约过期后按原检查点恢复执行。回归见 `tests/test_ecn_execution_recovery.py`。
